= FFMPEG NEXT API

A web service for converting audio/video/image files using FFMPEG.

Based on:

* https://github.com/surebert/docker-ffmpeg-service
* https://github.com/jrottenberg/ffmpeg
* https://github.com/fluent-ffmpeg/node-fluent-ffmpeg

Fork on:

* https://github.com/samisalkosuo/ffmpeg-api

NOTE: This README covers endpoints and parameters at a reference level. Full cURL examples (plus n8n integration snippets and sample JSON payloads) for every endpoint live in the API's built-in documentation page, served at the service root (`GET /`) once the API is running — that's the `index.html` included in this repo, which appears at the default directory when installed.

== New Features in This Fork

The following endpoints were added on top of the original project:

=== POST /image/to/scroll-video

Receives a tall image (e.g. a webpage screenshot) and generates a smooth top-to-bottom scrolling MP4 video.

Query params: `velocidade` (px/s, default 180), `crf` (0–51, default 20), `largura` (px, default 1080), `altura` (px, default 1920), `fps` (default 30).

=== POST /image/to/images-to-video

Creates a video slideshow from multiple uploaded images. Each image is displayed for an equal portion of the requested total duration.

Query params: `totalDuration` (required, seconds), `width` (default 1920), `height` (default 1080), `fps` (default 30), `crf` (default 20), `scale` (contain/cover/stretch/fill, default contain), `transition` (true/false, default false).

=== POST /subtitle/ass

Burns or soft-attaches subtitles to a video with full ASS styling, effects, karaoke highlighting, and typewriter animations. Accepts ASS, SRT, or plain text.

=== POST /video/add/audio

Adds up to 5 audio tracks to a video with per-track control over volume, trim, delay, loop, fade, and playback rate. Supports mix and streams modes, ducking (automatic music reduction during speech), crossfade between tracks, normalization, and afterVideo extensions (freeze/color/image) when the audio outlasts the video.

No FFmpeg knowledge required — describe the result in JSON and the API builds all filters automatically.

=== POST /convert/video

Professional, format-agnostic video transcoding. Convert to any FFmpeg-supported container, and optionally change resolution/orientation/resize-mode/background, video codec/quality/preset/fps/color-space/HDR/rotation/flip, audio codec/bitrate/channels/sample-rate (or remove audio entirely), and metadata — all through JSON, no FFmpeg flags required. Replaces the old, fixed `POST /convert/video/to/mp4`.

Accepts **4 input sources** (exactly one per request):

* `video` — multipart file upload
* `base64` — base64 string (plain, or a `data:video/mp4;base64,...` URI)
* `url` — fetches the video from a remote http/https URL
* `localFile` — a path relative to the `uploads/` directory (mounted as a Docker volume — see below), for sharing files with other containers such as n8n without an HTTP upload

Two request shapes work against the same path:

* `multipart/form-data`: the source above as a file/field, plus an optional `config` text field (JSON, same shape as the JSON body below), plus an optional `backgroundImage` file field (only used with `resolution.background.mode="image"`).
* `application/json`: the body *is* the config object, with the source as a sibling top-level key (`base64`, `url`, or `localFile`).

All config fields are optional — an empty request converts to MP4, H.264/CRF 20/preset medium, AAC 192k, preserving the source resolution, fps, color space, and orientation as closely as possible.

.config JSON — every field optional
----
{
  "format": "mp4",
  "resolution": {
    "preset": "1080p",
    "orientation": "auto",
    "custom": { "width": 1600, "height": 900 },
    "resizeMode": "contain",
    "keepAspectRatio": true,
    "background": { "mode": "color", "color": "#000000", "strength": 20, "image": { "url": "https://…" } }
  },
  "video": {
    "codec": "h264",
    "quality": { "mode": "crf", "value": 20 },
    "preset": "medium",
    "fps": 30,
    "colorSpace": "bt709",
    "hdr": "auto",
    "rotation": "auto",
    "flip": "none"
  },
  "audio": { "codec": "aac", "bitrate": "192k", "channels": 2, "sampleRate": 48000, "remove": false },
  "metadata": { "mode": "copy" }
}
----

**format** — output container. One of: `mp4`, `mov`, `mkv`, `avi`, `webm`, `flv`, `wmv`, `mpeg`, `mpg`, `ts`, `m2ts`, `mts`, `3gp`, `ogv`, `gif`, `apng`, `nut`, `asf`, `vob`, `dv`, `f4v`, `mxf`. Default `mp4`. Codec compatibility per container is validated automatically (friendly error if incompatible); `gif`/`apng`/`dv` force their own codec regardless of `video.codec` (warning returned, not an error), and `gif`/`apng` always drop audio. Less common containers (`wmv`, `asf`, `mpeg`, `mpg`, `vob`, `ogv`, `nut`, `mxf`, `dv`, `f4v`) are best-effort — FFmpeg's support for them is narrower than for `mp4`/`mkv`/`webm`.

**resolution.preset** — `original` (default, no scaling), `480p`, `720p`, `1080p`, `1440p`, `2160p`, or `custom` (requires `resolution.custom.width`/`height`, or `width`/`height` directly under `resolution`).

**resolution.orientation** — `auto` (default), `horizontal`, or `vertical`; swaps width/height of the chosen preset. `auto` detects the source's own portrait/landscape shape and matches it — a 9:16 source asking for `"720p"` gets 720x1280, not 1280x720 with the sides padded away. Ignored (with a warning) when `preset="custom"`.

**resolution.resizeMode** — CSS `object-fit`-style behavior when the source aspect ratio doesn't match the target: `contain` (default, letterbox/pillarbox with `background`), `cover` (crop to fill), `stretch` (distort to fill), `fitWidth` (fixed width, auto height), `fitHeight` (fixed height, auto width), `original` (force no scaling regardless of `preset`).

**resolution.keepAspectRatio** — default `true`. Setting it to `false` forces `stretch` behavior even when `resizeMode` is `contain`/`cover`.

**resolution.background** — only relevant for `resizeMode="contain"`. `mode`: `color` (default, `color` hex, default `#000000`), `blur` (`strength` 0–100), or `image` (`image`: `{base64|url|localFile}`, or multipart field `backgroundImage`).

**video.codec** — `h264` (default), `hevc`, `av1`, `vp9`, `mpeg4`, `prores`, `copy`. `copy` is only used when explicitly requested, and only when nothing else forces a re-encode (resolution change, rotation/flip, fps change, colorSpace change, `hdr:"remove"`) — combining `copy` with any of those returns a clear validation error instead of silently ignoring your request.

**video.quality** — one of three modes, not applicable to `prores`/`copy`:

* `{"mode":"crf","value":0-51}` (0-63 for `vp9`/`av1`) — constant quality. **Default** `{"mode":"crf","value":20}`.
* `{"mode":"bitrate","value":"8M"}` — fixed video bitrate.
* `{"mode":"maxSize","value":50}` — target a maximum **output file size**, in megabytes (e.g. `50` → ≈50MB regardless of input size). The video bitrate is computed automatically from the probed source duration, minus an estimate of the audio track's share of the budget — no need to calculate bitrates by hand. Treated as a best-effort ceiling (~5% safety margin), not an exact guarantee — a request unrealistically low for the video's duration falls back to a minimum viable bitrate (with a warning in `X-Warnings`) rather than producing a broken file.

**video.preset** — encoder speed/efficiency preset: `ultrafast` … `veryslow`. Default `medium`. Mapped automatically per codec family (x264/x265 use it directly; vp9/av1 use their own numeric scales).

**video.fps** — `source` (default, preserves original) or `24`/`25`/`30`/`50`/`60`.

**video.colorSpace** — `source` (default), `bt601`, `bt709`, `bt2020`.

**video.hdr** — `auto` (default: keeps HDR unless the target container has essentially no real HDR support, in which case it tonemaps down to SDR bt709), `keep`, `remove` (always tonemaps to SDR bt709 — requires FFmpeg built with `zscale`/libzimg).

**video.rotation** — `auto` (default), `0`, `90`, `180`, `270`. **video.flip** — `none` (default), `horizontal`, `vertical`, `both`.

**audio.codec** — `aac` (default), `mp3`, `opus`, `flac`, `pcm`, `copy`. **audio.bitrate** — e.g. `"192k"` (default for lossy codecs). **audio.channels** — `1`/`2`/`6`/`8`. **audio.sampleRate** — `22050`/`32000`/`44100`/`48000`/`96000`. **audio.remove** — `true` strips audio entirely.

**metadata.mode** — `copy` (default) or `remove`.

The response is the converted file (same download behavior as every other `/convert/*` endpoint), plus informational headers: `X-Original-Format`, `X-Original-Resolution`, `X-Output-Format`, `X-Output-Resolution`, `X-Video-Codec`, `X-Audio-Codec`, `X-Output-Fps`, `X-Output-Duration`, `X-Warnings` (JSON array — e.g. when a codec was overridden by the container, or `copy` couldn't be honored).

=== POST /convert/audio

Converts any FFmpeg-supported audio input to any supported output format. Replaces the old, fixed `POST /convert/audio/to/mp3` and `POST /convert/audio/to/wav`. Same input sources, request shapes, and response convention as `POST /convert/video` above (multipart file / base64 / url / localFile; `multipart/form-data` with a `config` field, or a plain `application/json` body).

**format** — one of: `mp3`, `wav`, `aac`, `m4a`, `flac`, `ogg`, `opus`, `wma`, `aiff`. Default `mp3`. The codec is implied by the format — no separate codec field to worry about.

**quality** — three modes:

* `{"mode":"default"}` (or omit `quality` entirely) — no quality reduction. Uses this API's standard 192k for lossy formats, or a true lossless encode for `wav`/`flac`/`aiff`. This is also the fallback when nothing at all is specified.
* `{"mode":"reduce","value":40}` — reduces the bitrate by that percentage (1-99) relative to the 192k baseline. Not applicable to lossless formats.
* `{"mode":"maxSize","value":10}` — targets a maximum **output file size**, in megabytes, the same way `video.quality.mode="maxSize"` works on `/convert/video`: the bitrate is computed automatically from the probed source duration. Not applicable to lossless formats.

The response is the converted file, plus headers: `X-Original-Format`, `X-Output-Format`, `X-Audio-Codec`, `X-Audio-Quality`, `X-Output-Duration`, `X-Warnings`.

=== POST /convert/image

Generic image conversion/processing endpoint. Replaces the old, fixed `POST /convert/image/to/jpg`. Same architecture as `/convert/video` and `/convert/audio` (FFmpeg only — this API has never used a separate image library, see `image.js`'s existing scale filters, which the crop/resize logic here builds on): 4 input sources, dual JSON/multipart transport, same response convention. The multipart file field is named `file` (matching the other simple endpoints in this API and the example below), with an optional `watermark` file field.

**format** is the only required setting — it can be given either as a query parameter (`?format=jpg`, the simplest form) or inside the JSON config. Everything else is optional and defaults to "do nothing extra": no resize, no crop, no watermark, no rotation, no flip, no additional compression.

Input format is always auto-detected from the file's actual content (never from its extension) via the same FFmpeg probe already used by every other endpoint in this API.

**Supported output formats**: `jpg`, `jpeg`, `png`, `webp`, `avif`, `bmp`, `gif`, `tiff`, `tif`, `ico`, `ppm`, `pgm`, `pbm`. `svg` is intentionally **not** offered — it's a vector format and FFmpeg has no raster encoder for it; requesting it returns a clear error explaining why. `webp` and `avif` additionally depend on the FFmpeg build having `libwebp`/`libaom-av1` compiled in — if missing, FFmpeg itself returns a clear encoder-not-found error.

.config JSON — every field optional except (implicitly) `format`
----
{
  "format": "jpg",
  "quality": 85,
  "compression": { "maxSize": "1MB", "targetReduction": 50, "allowResolutionReduction": false },
  "resize": { "percentage": 50, "maxWidth": 1920, "maxHeight": 1080, "width": 1200, "height": 800, "resizeMode": "contain" },
  "rotation": 90,
  "flip": "horizontal",
  "crop": { "aspectRatio": "1:1" },
  "watermark": { "file": "logo.png", "position": "bottom-right", "size": 20, "opacity": 1.0 }
}
----

**quality** — 1-100, only for `jpg`/`webp`/`avif` (the only formats with a real quality knob). Default `85`. Ignored (with a warning) for lossless formats.

**compression** — mutually exclusive size-targeting modes; `maxSize` wins if both are given:

* `maxSize`: `"500KB"`, `"1MB"`, `"5MB"`, `"20MB"` — binary-searches the quality (bounded to 6 passes) for the highest value that still fits, without ever entering an unbounded loop.
* `targetReduction`: `10`-`80` (%) — measures the original file size and searches for that percentage reduction, using the exact same search as `maxSize`.
* `allowResolutionReduction` (default `false`) — if the target still isn't reachable through quality alone, permits shrinking the resolution (in bounded steps, up to 3 extra rounds) to get there. Never applied unless explicitly set to `true`. This is also the *only* lever available for lossless formats (`png`/`bmp`/`gif`/`tiff`/`ico`/`ppm`/`pgm`/`pbm`), since they have no quality knob at all.
* Treated as a **target**, not an exact guarantee — if it truly can't be reached without extreme degradation, the API returns its best effort plus a warning in `X-Warnings`, never a broken file.

**resize** — pick exactly one mode (never distorts the image unless `resizeMode="stretch"` is explicitly chosen):

* `percentage`: `1`-`500` — scales width and height proportionally (`50` = half size, `150` = 150%, upscaling included).
* `maxWidth` / `maxHeight` (either or both together) — a ceiling: only downscales if the image actually exceeds it, preserving aspect ratio. Never upscales.
* `width` + `height` together — an exact target box, honoring `resizeMode`: `contain` (default, preserves aspect, letterboxes with black), `cover` (preserves aspect, crops to fill), `stretch` (fills exactly, distorts).

**rotation** — `0` (default), `90`, `180`, `270`. Correctly accounts for the width/height swap at 90°/270° for any crop/resize/watermark that follows.

**flip** — `none` (default), `horizontal`, `vertical`, `both`.

**crop** — `aspectRatio`: `1:1`, `4:5`, `16:9`, `9:16`, `4:3`, or `custom` (with `width`/`height` given as a *ratio*, e.g. `3:2` — not literal pixel dimensions; the API always crops the largest possible centered area at that ratio, never distorting).

**watermark** — `file`: a path string (shorthand for `localFile`) or `{base64|url|localFile}` object, or upload it as the multipart field `watermark`. `position`: `top-left`, `top-right`, `bottom-left`, `bottom-right`, `center` (default `bottom-right`), or `custom` with `x`/`y` in pixels (rejected if it would place the watermark fully outside the image). `size`: percent of the main image's width (default `20`), or `sizePixels` for an exact pixel width. `opacity`: `0`-`1` (default `1.0`, fully opaque).

**Processing order**: rotate → flip → crop → resize → watermark → compression → export — chosen to avoid unnecessary quality loss (e.g. cropping before resizing means the crop math always works off full-resolution pixels).

The response is the converted file, plus headers: `X-Original-Format`, `X-Output-Format`, `X-Original-Size`, `X-Output-Size`, `X-Size-Reduction-Percent`, `X-Original-Resolution`, `X-Output-Resolution`, `X-Rotation-Applied`, `X-Watermark-Applied`, `X-Crop-Applied`, `X-Warnings`.

FFMPEG API is provided as Docker image for easy consumption.

== Endpoints

* `GET /` - API Readme.
* `GET /endpoints` - Service endpoints as JSON.
* `POST /video/extract/audio` - Extract audio track from POSTed video file. Returns audio track as 1-channel wav-file.
** Query param: `mono=no` - Returns audio track, all channels.
* `POST /video/extract/images` - Extract images from POSTed video file as PNG. Default FPS is 1. Returns JSON that includes download links to extracted images.
** Query param: `compress=zip|gzip` - Returns extracted images as _zip_ or _tar.gz_ (gzip).
** Query param: `fps=2` - Extract images using specified FPS. 
* `GET /video/extract/download/:filename` - Downloads extracted image file and deletes it from server.
** Query param: `delete=no` - does not delete file.
* `POST /probe` - Probe media file, return JSON metadata.

== Docker image

=== Build your own

* Clone this repository.
* Build Docker image:
** `docker build -t ffmpeg-api .`
* Run image in foreground:
** `docker run -it --rm --name ffmpeg-api -p 3000:3000 ffmpeg-api`
* Run image in background:
** `docker run -d --name ffmpeg-api -p 3000:3000 ffmpeg-api`

=== Use existing

* Run image in foreground:
** `docker run -it --rm --name ffmpeg-api -p 3000:3000 kazhar/ffmpeg-api`
* Run image in background:
** `docker run -d --name ffmpeg-api -p 3000:3000 kazhar/ffmpeg-api`

=== Environment variables

* Default log level is _info_. Set log level using environment variable, _LOG_LEVEL_.
** Set log level to debug:
** `docker run -it --rm -p 3000:3000 -e LOG_LEVEL=debug kazhar/ffmpeg-api`
* Default maximum file size of uploaded files is 512MB. Use environment variable _FILE_SIZE_LIMIT_BYTES_ to change it:
** Set max file size to 1MB:
** `docker run -it --rm -p 3000:3000 -e FILE_SIZE_LIMIT_BYTES=1048576 kazhar/ffmpeg-api`
* All uploaded and converted files are deleted when they've been downloaded. Use environment variable _KEEP_ALL_FILES_ to keep all files inside the container /tmp-directory:
** `docker run -it --rm -p 3000:3000 -e KEEP_ALL_FILES=true kazhar/ffmpeg-api`
* When running on Docker/Kubernetes, port binding can be different than default 3000. Use _EXTERNAL_PORT_ to set up external port in returned URLs in extracted images JSON:
** `docker run -it --rm -p 3001:3000 -e EXTERNAL_PORT=3001 kazhar/ffmpeg-api`
* `POST /convert/video` with source `localFile` reads from the directory in _UPLOADS_DIR_ (default: `uploads/` inside the container's working directory — see `docker-compose.yml`, which mounts `./uploads` there).
* `POST /convert/video` with source `url` uses _URL_FETCH_TIMEOUT_MS_ (default 30000) and _URL_MAX_REDIRECTS_ (default 5).


== Usage

Input file to FFMPEG API can be anything that ffmpeg supports. See https://www.ffmpeg.org/general.html#Supported-File-Formats_002c-Codecs-or-Features[ffmpeg docs for supported formats].

=== Convert

For video, see `POST /convert/video` above (replaces the old fixed `/convert/video/to/mp4`). For audio, see `POST /convert/audio` above (replaces the old fixed `/convert/audio/to/mp3` and `/convert/audio/to/wav`). For images, see `POST /convert/image` above (replaces the old fixed `/convert/image/to/jpg`). All three offer full control over format/codec/quality instead of a single fixed output.

=== Extract images

`POST /video/extract/images` extracts images from a video. Returns JSON listing a download URL for each extracted image, unless `compress=zip` or `compress=gzip` is used, in which case it returns a single archive instead. Default FPS is 1; images are PNG. See sample: link:./samples/extracted_images.json[extracted_images.json].

`GET /video/extract/download/:filename` downloads one extracted image and deletes it from the server, unless `delete=no` is passed.

=== Extract audio

`POST /video/extract/audio` extracts the audio track from a video as a WAV file — 1 channel (mono) by default, or all channels with `mono=no`.

=== Probe

`POST /probe` returns full JSON metadata for any media file — the same output as `ffprobe -of json -show_streams -show_format`. See sample: link:./samples/probe_metadata.json[probe_metadata.json].
